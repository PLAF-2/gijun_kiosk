# 전국 극장 선택과 다양한 상영 일정·좌석도

## 목표와 범위
기존 영화 포스터와 예매·전화번호 조회·취소·7종 결제 시연을 유지하면서 포스터 다음에 지역·극장 선택을 추가한다. 실제 결제나 실시간 극장 시스템을 연동하지 않는다. 기존 남색 터치 UI를 사용한다.

## 사용자 흐름
첫 화면 → 영화 목록 → 포스터 터치 시 지역·극장 선택 → 날짜·상영 시간 → 관람 인원·좌석 → 예매 확인과 휴대폰 번호 → 결제 방식과 안내 → 완료.
영화 변경은 극장·회차·좌석 선택을 초기화한다. 극장 변경은 날짜를 유지하되 회차·좌석을 초기화한다. 날짜와 회차 변경은 기존 좌석을 초기화한다. 이전 버튼은 선택을 유지해 해당 단계로 돌아간다.

## 지역과 극장
서울·부산·대구·인천·광주·대전·울산·세종·경기·강원·충북·충남·전북·전남·경북·경남·제주 17개 지역을 제공한다. 각 지역에 4개, 총 68개 극장을 제공한다. 사용자가 승인한 지역명 기반 시연 지점명을 사용하며 추가 요청에 따라 강남 CINEMA처럼 지역 이름 뒤에 CINEMA를 붙인다.
지역 선택과 극장 목록을 한 화면에 배치한다. 선택한 영화의 작은 포스터와 제목을 표시하고, 극장 선택 후 날짜·시간으로 이동한다. 극장마다 지역, 고유 ID, 이름, 간단한 위치 정보와 3~5개 상영관을 가진다.

## 상영 일정
극장·날짜별로 모든 영화의 일정을 함께 생성하고 해당 영화의 회차만 보여 준다. 상영관별 영화 러닝타임과 정리 시간을 반영해 겹치는 회차를 만들지 않는다. 일정은 극장·날짜에 따른 결정적 계산을 사용해 재렌더링·새로고침 때 변하지 않는다. 날짜에 따라 시작 시각, 회차 수, 배정 상영관과 잔여 좌석을 다양하게 구성한다.
기존 7일 날짜 선택을 유지한다. 회차 카드에 시작·종료 시간, 상영관, 잔여/전체 좌석을 표시한다. 상영관 총 좌석 수는 날짜에 따라 바꾸지 않는다. 미리 예매된 시연 좌석은 회차별로 다르게 만들고 실제 로컬 예매 좌석을 합쳐 잔여 좌석을 계산한다. 매진 회차는 선택 불가, 회차가 없으면 다른 날짜 안내를 표시한다. 기존 일반 2D 예시 요금을 유지한다.

## 좌석도
각 상영관에 고정된 좌석 배치 데이터를 둔다. 약 60~180석의 소·중·대형 배치, 행별 빈 공간, 중앙·측면 통로를 제공한다. 좌석은 행과 번호가 붙은 실제 선택 가능한 데이터로 구성한다. 상영관이 다르면 좌석 수와 배치도 달라진다.
스크린, 좌우 행 표기, 좌석 번호, 선택 가능·선택됨·예매됨 상태를 표시한다. 확대·축소와 가로·세로 이동으로 모바일 영화 예매처럼 전체 배치와 개별 좌석을 확인할 수 있게 한다. 좌석은 키보드로도 선택할 수 있고 예매된 좌석은 비활성화한다. 기존 최대 8명과 정확한 인원 수만큼 선택하는 규칙을 유지한다.

## 저장·조회·취소
상영 회차 ID에 극장·날짜·상영관·시각을 포함해 지점 간 좌석 점유가 섞이지 않게 한다. 새 예매에는 극장 ID·이름·지역 스냅샷을 저장하고 확인·완료·조회 화면에 표시한다. 전화번호 조회의 복수 내역에도 극장을 표시한다. 취소하면 해당 회차의 로컬 예매 좌석만 해제한다.
기존 저장 키와 v1 예매 기록을 유지한다. 새 극장 필드는 선택적으로 검증해 이전 기록도 번호·휴대폰 조회와 취소가 가능하게 한다. 좌석 ID 검증의 기존 A~D/1~8 한계를 확장한다. 저장 실패 경고를 유지한다.

## 구조와 완료 기준
극장 목록·상영관 배치·일정 계산은 UI와 분리된 cinema 데이터 모듈로 구성한다. 지역·극장 선택 화면을 추가하고 부모 앱의 단계·뒤로 가기·초기화 규칙을 연결한다. 좌석 화면은 상영관 배치를 직접 렌더링한다.
완료 기준: 17개 지역 각각 4개 극장, 포스터에서 극장 선택 이동, 극장·날짜에 따른 일정 차이, 상영관별 고정된 다양한 좌석도, 안정적인 회차 ID, 극장별 점유 분리, 모든 예매 요약의 극장 표시, 기존 조회·취소·결제 흐름 유지. 요청 전 자동 테스트를 추가하거나 실행하지 않는다. 타입·프로덕션 빌드와 변경 코드 검토로 구현 상태를 확인한다. GitHub 푸시는 별도 요청 때 수행한다.

## 설계 검토
총 좌석과 잔여 좌석을 구분했고, 새 선택 단계의 초기화·뒤로 가기·저장 호환 규칙을 명시했다. 사용자는 구현 진행과 지역명 뒤 CINEMA 명명을 승인했다.
